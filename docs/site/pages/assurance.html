Document assurance

Test template changes, explain rendered fields, compare outputs and preserve evidence. These capabilities have bounded contracts; passing a suite does not prove correctness for every possible document.

Validate input contracts and business rules

The SDK exposes validateContract(schema, data), contractTypeScript(schema) and contractSample(schema). Supported explicit types are object, array, string, number, integer, boolean and null. Properties, required keys, additionalProperties, enum, numeric bounds, string lengths and array lengths are supported. Unknown keywords, references, unions, regular expressions and unsupported combinations fail closed. Integer values must be safe JavaScript integers. Generated TypeScript describes structure; runtime validation enforces constraints. Samples are deterministic structural examples, not exhaustive or realistic test data.

const schema = {
  type: 'object', additionalProperties: false,
  properties: { total: { type: 'number', minimum: 0 } },
  required: ['total']
};
const validation = validateContract(schema, { total: 12.5 });
const checks = evaluateAssertions(
  { total: 12.5, lines: [{ amount: 10 }, { amount: 2.5 }] },
  [{ name: 'balanced', left: { sum: '/lines', field: '/amount' },
     operator: 'equals', right: { path: '/total' }, tolerance: 0.000001 }]
);

Assertion paths use RFC 6901 JSON Pointers. Calculations use JavaScript numbers, not a decimal money engine. Declare rounding and tolerances appropriate to your application. Contract and assertion results must be checked before rendering or delivery.

Explain values without exposing data by default

traceTemplateInputs(template, data) provides inspector-discovered preflight fields and scalar formatter evaluation. renderWithTrace(template, data, renderOptions, traceOptions) records actual standard lookup operations, their scoped paths, document parts, scope depth, formatter names, types, missing inputs and failures. Output values are excluded unless includeValues: true. Event and value limits are explicit; inspect truncated and droppedEvents.

Execution traces do not cover every legacy binding, infer original array indexes, or identify PDF page coordinates. A successful lookup does not prove that its result is visible on a rendered page. Rendering returns either {ok: true, value, trace} or {ok: false, error, trace}.

Customer regression suites and comparisons

const result = await runRegressionSuite(template, [
  { name: 'empty order', data: { items: [] }, approved: approvedBytes },
  { name: 'unicode customer', data: customerData, approved: unicodeBytes }
]);
if (!result.passed) throw new Error('Template change rejected');

Expected documents must be independently approved. Exact bytes are the default comparison. Explicit semantic mode compares text, spreadsheet values and formulas at positional locations; it does not assess formatting, images or page layout. Exact location masks are recorded, stale masks fail, and masks cannot exclude the entire document. Row insertion can produce multiple positional differences; there is no inferred business row identity.

comparePageImages(beforePng, afterPng, options) compares bounded PNG pixels. comparePdfDocuments(beforePdf, afterPdf, {pdftoppmPath: '/usr/bin/pdftoppm'}) rasterizes real PDF pages with Poppler and compares them, reporting page counts and renderer version. Configure executable paths only in trusted application code. Thresholds and rectangular masks must be explicit. Identical rasterization is not proof of document accessibility or correctness.

Replay a captured render

createReplayBundle(template, data, options) stores the template, data, attachments, options, exact output digest and engine identity. replayBundle(bundle) verifies integrity, rejects environment mismatches and confirms the output digest. Bundles contain potentially sensitive data and are not automatically uploaded.

Replay covers native renderer output. The engine fingerprint binds source/build bytes, lockfile, Node version, platform and architecture. Source and compiled builds intentionally have different identities. PDF converters and fonts are not captured. A digest detects corruption; it does not authenticate an author who can rewrite a bundle and recompute its digest.

Migrate with evidence and explicit incompatibilities

migrateCarboneText(source, options) inventories and converts a conservative scalar text subset. compileCarboneText enforces the declared input contract at render time. Case formatter migration requires declared string fields and en-US settings: a downloaded Carbone 3.8.2 runtime showed that Carbone accepts numeric case inputs while our engine requires strings. Unsupported loops, expressions and formatter semantics produce diagnostics and are not silently translated.

inventoryCrystalMetadata accepts the documented imprint-crystal-inventory-v1 JSON interchange for fields, formulas, groups and subreports. It is an inventory tool, not a native SAP export schema or a raw .rpt parser. Crystal extraction through an available licensed SDK and representative real reports remains separate work. See SAP documentation and Carbone version lifecycle.

DOCX supports the exact sibling-paragraph conditional pair {d.field:ifNEM():showBegin} and {d.field:showEnd}. Null, missing, empty string, empty array and empty object hide the block; zero and false retain it. Nested conditions, conditions mixed with repeats in a story, and unsafe document anchors reject explicitly.

Pinned rich DOCX components

assembleDocxComponents(host, components) inserts versioned, SHA-256-pinned DOCX fragments at whole top-level body paragraphs containing {{>clause@1}}. Each component has id, version, document, sha256; the result contains document and a lock with occurrence counts. Assemble before passing the result to render.

Paragraph styles, tables, embedded PNG/JPEG and ordinary numbered lists are imported with fresh identities; lists restart per occurrence. Host and fragment document defaults, and any referenced themes, must match. The host controls page settings. Nested components, notes/comments, fields/bookmarks, tracked changes, external links, custom sections and picture bullets are unsupported and rejected. LibreOffice checks cover an independently authored fixture; Microsoft Word acceptance remains pending.

inspectCrystalArtifact(bytes) inventories bounded CFB v3/v4 directory names, kinds and declared sizes. Three real RPT samples match an independent olefile oracle. This does not decode formulas, layout or stream content, render reports, or establish Crystal compatibility. Extended DIFAT is unsupported. Semantic migration still needs a supported SAP runtime and reference outputs.

Pinned reusable text components

ComponentRegistry expands exact-version references such as {{> address@v1}}, produces component hash locks and reports templates transitively affected by a component version. Missing dependencies, cycles, malformed references and excessive expansion fail. Registry entries are snapshots. This implementation handles text composition; merging Office styles, relationships, numbering and document fragments is not supported.

Validate before returning an artifact

validateDelivery(bytes, validators) snapshots the artifact, runs each required trusted validator and returns a digest-bound evidence report. Failed, timed-out, thrown or malformed checks produce status: 'quarantined' and no artifact. Validators receive separate byte copies. This is an in-memory handoff, not a durable quarantine store or a modification to existing job delivery routes. Applications must call it before their own delivery step.

pdfStructureValidator checks PDF parsing and page bounds only. veraPdfValidator({executable, version, profile}) invokes a locally installed trusted veraPDF executable without a shell and requires the expected core version and profile in its report. Set version to veraPDF's core releaseDetails version; the CLI application version can differ. Missing tools, report mismatches and parsing errors fail closed.

PDF/A and PDF/UA checks require the corresponding output and validation profile. Machine checks do not replace human accessibility review. This release does not claim to generate universally compliant PDF/A or PDF/UA. veraPDF validation scope.

Filter and export the same report data

createReportSnapshot(definition, filters) supports a bounded typed table with equality, substring and numeric range filters. It computes selected-row totals and a digest. reportSnapshotHtml(snapshot) creates a self-contained browser view with row details, search, selected CSV/data downloads and print-to-PDF. HTML escapes input, uses a script hash policy, and does not make external requests. CSV export guards against formula injection.

renderReportSnapshot(template, snapshot) validates the snapshot and binds it under d.report for Office or text exports. A browser selection downloads a report definition; pass that definition to createReportSnapshot before exporting through the SDK. Browser print is a browser PDF, not the Office template layout. Filtering is not access control: distribute only data the recipient may inspect. Numeric totals use compensated floating-point summation.

Verify AI-proposed edits

reviewTemplateCandidate(base, candidate, approvedCases) inspects a proposed template and runs its approved fixtures. acceptTemplateCandidate(review, currentBase) only returns bytes for a passing in-process review with an unchanged base. Public report mutation cannot turn a failed review into an accepted candidate. Persisted reviews must be re-run. No model-generated JavaScript is executed and no template is automatically published.

This is a provider-neutral verification interface, not an included LLM service, prompt editor or autonomous authoring agent. It works with candidate files produced by either people or AI tools.

Authenticated API and CLI

POST /v1/assurance uses the existing bearer authentication and concurrency limit. Operations run in a worker with a 30-second deadline and a 12 MiB request limit. Unknown properties fail. Binary fields use canonical base64; artifact responses use base64. Report HTML is returned inside JSON, not served as an executable page.

The CLI accepts the same JSON operation payload and writes a new private evidence file. It refuses to overwrite an existing file. A successful CLI invocation means the operation completed; inspect returned validation, passed or status fields before accepting an artifact.

Release gates and remaining acceptance

The implementation branch is not a production release. Required evidence includes typecheck/build, adversarial units, cross-feature API tests, all existing format corpora, independent Office/PDF checks, browser interaction and remote CI. Production acceptance additionally needs representative customer templates and approved visual baselines. Microsoft Office repair-free opening and human accessibility acceptance cannot be inferred from Linux rendering tests.

Research distinguishes observed runtime behavior, documented capabilities and our own design choices. No feature-count comparison or passing test count establishes universal compatibility with Crystal Reports or Carbone.
