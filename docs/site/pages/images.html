Images first

Images that follow your data.

Insert a placeholder picture, bind its description, and provide PNG or JPEG bytes. Keep layout decisions in the template.

Bind a picture

Set its alternative-text description to {d.logo}. In OpenDocument use the frame description. Supply base64 bytes in HTTP attachments.logo, or a Uint8Array in the SDK. data.logo can point to another attachment key. Missing optional bindings retain their placeholder. Remote image fetching and SVG are unsupported. 

{
  "data": {"logo":"brand"},
  "attachments": {"brand":"BASE64_PNG"},
  "images": {
    "brand": {"fit":"contain", "background":"#ffffff"}
  }
}

Fit, crop and rotate

Option Behavior
contain Preserve aspect ratio and pad to the picture canvas.
cover Preserve aspect ratio and crop centrally to fill the canvas.
fill Stretch to the canvas dimensions.
width / height Raster dimensions, 1–4,096 pixels. Template placement geometry is retained.
crop Integer left, top, width, height; applied after EXIF auto-orientation.
rotate Degrees from −360 to 360 after cropping.
background Hex RGB or RGBA background; transparency otherwise preserved.

When fit is requested without pixel dimensions, Imprint uses the bound picture extent if available. Supply dimensions explicitly for drawings without a readable extent. Transformed images are encoded as PNG. Untransformed images retain original bytes except when EXIF orientation requires normalization. Decoding, pixel dimensions and output size are bounded.

Images inside repeats

Use {d.items[i].image} and an attachment key on each item. DOCX clones picture identities. XLSX clones pictures wholly anchored within a pattern row and shifts them by the multi-row block height. Pictures crossing a repeat boundary fail explicitly. PPTX slide repeats and ODF repeated frames resolve each image in the item scope.

QR and barcodes

POST /v1/barcode
{"type":"qrcode","text":"https://example.com/invoice/123","scale":3}

The response is a PNG ready to pass as an image attachment. Supported types: qrcode, code128, ean13 and datamatrix. Scale is 1–6; UTF-8 text is bounded at 512 bytes, with Code 128 additionally limited to 100 characters. Invalid checksums or unencodable input return a typed error.

Image transformations use Sharp; barcode rasterization uses bwip-js. Template binding and package relationship handling live in this codebase.
