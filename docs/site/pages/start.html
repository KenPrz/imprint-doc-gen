One-container quick start

The standalone image bundles the API, SQLite queue and PDF converter. The private registry package requires an account with package read access. Use a tested commit tag or image digest in production. 

docker login ghcr.io -u YOUR_GITHUB_USERNAME
docker pull ghcr.io/kenprz/imprint-doc-gen:standalone
# Set IMPRINT_API_KEY to a secret of at least 24 characters.
docker run -d --name imprint-doc-gen --restart unless-stopped \
  --stop-timeout 120 --memory 2g --cpus 2 --pids-limit 384 \
  --read-only --tmpfs /tmp:rw,size=768m,mode=1777 \
  --cap-drop ALL --security-opt no-new-privileges:true \
  -p 127.0.0.1:8088:3000 -e IMPRINT_API_KEY \
  -v imprint-data:/data \
  ghcr.io/kenprz/imprint-doc-gen:standalone
curl http://127.0.0.1:8088/ready

Put a TLS proxy in front of the loopback listener. Keep the named volume when replacing the container. One SQLite volume belongs to one service instance. Deployment options.

Your first document

  1. Write {d.customer.name} in a DOCX, XLSX, PPTX, ODT, ODS or ODP template.
  2. Encode the template as base64 and send it with {"customer":{"name":"Example Company"}}.
  3. Omit output to keep the template format, or use "pdf".
POST /v1/render
Authorization: Bearer YOUR_KEY
Content-Type: application/json

{
  "template": "BASE64_TEMPLATE",
  "data": {"customer": {"name": "Example Company"}},
  "output": "pdf"
}
