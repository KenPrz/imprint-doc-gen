Deployment

Standalone image

compose.standalone.yml starts the all-in-one image with persistent SQLite storage and bundled conversion. Set IMPRINT_API_KEY; optionally set IMPRINT_PORT and IMPRINT_IMAGE. The release workflow publishes linux/amd64 images after required checks pass. Pin a tested digest and back up before upgrades. 

docker compose -f compose.standalone.yml up -d --wait

Bundled and custom fonts

Both the standalone image and the separate converter include a pinned Google Fonts snapshot: 3,913 font files in 2,066 family directories, plus the base image's Noto, Liberation, Carlito and other fonts. Variable font files can provide multiple faces. The snapshot adds about 2.3 GiB before image compression and requires an initial download of about 1.6 GiB. Docker caches the verified archive and font layer. No font download occurs during document conversion. LibreOffice preloads the catalog before the service reports ready, with a 60-second startup budget. Allow up to 90 seconds for standalone readiness; request deadlines remain unchanged.

Sources, revision, expected file count, and SHA-256 are pinned in docker/fonts/sources.lock.json. The build preserves the original font files, metadata, family license/notice files, and shared OFL, Apache, and Ubuntu license texts under /usr/local/share/fonts/imprint/google/. A checksum mismatch or incomplete archive fails the build.

This does not imply full parity with Carbone's cloud service. Its 6,361-entry reference list includes independently licensed commercial fonts and names/styles absent from the pinned Google snapshot. Aptos and Calibri are not bundled by default. Microsoft's standalone Aptos download allows installation on your devices but explicitly grants no redistribution rights. Include independently licensed fonts only where your license permits the resulting image's use and distribution.

Every built image includes installed-fonts.json, carbone-coverage.json, and sources.lock.json in /usr/local/share/imprint/fonts/. The coverage report compares installed full names and primary family/style names against the reference. It does not count fallback aliases as coverage, and name matching alone does not prove identical glyphs, all language coverage, or identical Office layout. 

# Works without starting the API or providing an API key.
docker run --rm --network none --entrypoint cat imprint-doc-gen:standalone \
  /usr/local/share/imprint/fonts/carbone-coverage.json

# Fail if even one reference face name is missing; writes a fresh report in /tmp.
docker run --rm --network none --read-only --tmpfs /tmp \
  --entrypoint python3 imprint-doc-gen:standalone \
  /usr/local/lib/imprint-fonts/manage.py inventory --output /tmp/font-report --strict

To add fonts, put their TTF, OTF or TTC files and license/notice files in docker/fonts/custom/ before building. This directory is Git-ignored but is intentionally copied into both images. CI must receive those files separately if its images need them. Existing images and running containers do not acquire newly added files automatically: rebuild and recreate them. REQUIRED_FONTS is a comma-separated build argument that fails the build when an expected family is absent, rather than accepting a fontconfig substitute. 

# After supplying Aptos font files with suitable rights for this image:
docker build -f Dockerfile.standalone \
  --build-arg 'REQUIRED_FONTS=Roboto,Lobster,Open Sans,Noto Sans,Aptos' \
  -t imprint-doc-gen:custom-fonts .
IMPRINT_IMAGE=imprint-doc-gen:custom-fonts \
  docker compose -f compose.standalone.yml up -d --wait

# Separate converter builds use the same folder and argument.
docker build -f Dockerfile.gotenberg \
  --build-arg 'REQUIRED_FONTS=Roboto,Lobster,Open Sans,Noto Sans,Aptos' \
  -t imprint-doc-gen:converter-8.37.0-pdfcpu-0.16.1 .
docker compose -f compose.yml up -d --no-build --force-recreate gotenberg

CI converts a synthetic DOCX using Roboto, Open Sans, Lobster and Ubuntu and checks the resulting PDF's embedded font resources. Run npm run test:fonts for the installer and coverage unit checks. To validate your converter, run python3 scripts/font-smoke.py --url http://CONVERTER:3000; repeat --font "Family Name" to select your own families. Keep representative customer documents as separate visual acceptance tests.

Sources: Google Fonts collection and licenses, Carbone font-name reference, Microsoft Aptos download and included license.

Development and separate production services

docker compose up --build -d
# compose.override.yml adds source mounts, watch mode and a development key.
docker compose exec app npm test

# Production excludes the override and requires your secret.
docker compose -f compose.yml up --build -d --wait

Both use SQLite. Converter networking is isolated and has no published host port. Production containers have read-only roots and explicit resource limits.

PostgreSQL and S3

The optional cluster mode stores metadata and leases in PostgreSQL and immutable documents in a private S3-compatible bucket. Provision the bucket first. Grant only the required bucket/object permissions. Default AWS credential providers also support workload identity where available. 

# Set these through your deployment secret mechanism:
# IMPRINT_API_KEY, POSTGRES_PASSWORD (URL-safe), S3_BUCKET
# AWS_REGION, and AWS credentials or workload identity
# Optional S3_ENDPOINT for a compatible object service

docker compose -f compose.cluster.yml up --build -d --wait
docker compose -f compose.cluster.yml up -d --scale worker=2

The API serves requests; separate dist/worker.js processes drain jobs. PostgreSQL uses transactional claims with SKIP LOCKED and expiring leases. A stale attempt cannot publish over a newer attempt. S3 writes complete before successful job state is committed; downloads verify byte count and SHA-256. Staged/orphaned objects are tracked and cleaned after a one-hour grace period. Completed jobs and webhook records retain seven days.

Use a dedicated database. Initialization creates the imprint schema and rejects newer unknown schema versions. DATABASE_URL and IMPRINT_DATA_DIR are mutually exclusive. Use the verified offline migration command to copy an existing SQLite backup into an empty PostgreSQL/S3 deployment. Keep both services stopped during migration and switch traffic only after validation.

Configuration

Variable Purpose
IMPRINT_API_KEY Administrator key, minimum 24 characters.
IMPRINT_DATA_DIR SQLite directory; standalone defaults to /data.
DATABASE_URL · S3_BUCKET Enable PostgreSQL/S3 mode; API requires independent workers.
S3_ENDPOINT · AWS_REGION Optional compatible endpoint and region.
IMPRINT_CONCURRENCY 1–8 render slots per process; default 2.
GOTENBERG_URL Converter endpoint for separate services.
WEBHOOK_URL · WEBHOOK_SECRET Optional cluster-worker completion callback; HTTPS and a secret of at least 32 characters.
WEBHOOK_ALLOW_HTTP Explicit development-only opt-in for HTTP; not set by production Compose.

Signed completion events

The operator configures one fixed callback URL; callers cannot supply arbitrary URLs. It receives all tenants' terminal job events, without template/data bytes. Persisted events commit in the same transaction as job completion. Delivery is at least once: deduplicate by event ID. 

X-Imprint-Event-Id: EVENT_ID
X-Imprint-Timestamp: UNIX_SECONDS
X-Imprint-Signature: sha256=HEX_HMAC

{"id":"EVENT_ID","type":"job.succeeded","tenantId":"TENANT_ID",
 "jobId":"JOB_ID","status":"succeeded","format":"pdf","error":null}

Verify HMAC-SHA256 over timestamp + "." + rawBody with the shared secret, using a timing-safe comparison and a bounded clock tolerance. Return 2xx only after recording the event. Redirects are not followed; each attempt has a five-second deadline. Up to eight attempts use exponential backoff. Monitor imprint.webhooks for exhausted deliveries. Configuring a callback later can deliver retained events from the previous seven days.

Design references: PostgreSQL queue locking, node-postgres transactions, AWS S3 SDK.
