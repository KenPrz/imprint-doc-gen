Synthetic invoice and image testing

All templates are generated by scripts/generate-example.ts from the repository's
own package builders. Data, company names and images are fictional. No external
application, database or reference service is used.

12 cases
- Four scenarios each for DOCX invoices, XLSX invoices and DOCX signatures.
- Normal: 3 items. Empty: 0 items. Large: 15 items. Multilingual: Unicode text.
- PNG logos, direct PNG signatures, named attachment lookup, JPEG data URLs,
  and an omitted optional signature that preserves the placeholder.

Run with Node.js 24:
  npm run test:synthetic

This writes editable documents, fake JSON data, attachment maps, templates,
image assets, per-case results, summary.json and an offline index.html gallery
under artifacts/synthetic/. Outputs are gitignored.

To test a running service, set IMPRINT_URL and IMPRINT_API_KEY, then run:
  npm run test:synthetic -- --api --pdf

To test the SDK plus a converter, set GOTENBERG_URL, then run:
  npm run test:synthetic -- --pdf

PDF checks require pdfinfo, pdftotext, pdfimages and pdftoppm (poppler-utils).
Each PDF is checked and gets a first-page PNG preview. Credentials are not
written to results. --output selects an output directory. SYNTHETIC_TEST_SEED
changes deterministic example IDs. Image rasterization depends on host fonts.

CI runs all 12 semantic cases and seven standalone API/PDF smoke cases:
  npm run test:synthetic -- --api --pdf --smoke

Checks
- Valid package relationships and drawing identities.
- Inserted scalar values, no unresolved tags, expected table row counts.
- Picture dimensions and exact supplied image bytes in the Office package.
- Native XLSX amounts and calculated totals, including a zero-item total of 0.
- PDF page counts, company text and multilingual probes.
- Supplied images and all XLSX invoice column labels on the first PDF page.
- Deliberately wrong customer data, image bytes and totals fail the checker.

Limits
The suite tests rendering and example arithmetic, not business accounting,
production integration or sustained load. PDF image-presence checks do not
prove pixel-level equality. Inspect complete PDFs for page and font fidelity.
Nested repetition, package edge cases and formula semantics have separate
unit tests and the 200-level DOCX/XLSX corpus.
